# SG004 — DROP TABLE

A `DROP TABLE` statement removes the table definition and every row it
contains in a single, unrecoverable operation.

## Why it is dangerous

The schema and the data disappear together. Indexes, foreign-key constraints,
triggers, views, and permissions that were defined on the table are all removed
at the same time. Nothing in the script communicates what was lost; the only
record is the backup taken before the statement ran.

Unlike `DELETE`, which at least leaves the table structure intact, `DROP TABLE`
eliminates the target entirely. Code that references the table — application
queries, stored procedures, reporting jobs — will begin failing with
"relation does not exist" the moment the statement commits.

The operation is also fast, which removes any natural pause for reconsideration.
On a table with hundreds of millions of rows, `DROP TABLE` completes in
milliseconds because the engine discards the storage allocation rather than
removing rows one by one. The speed works against the operator.

## The safer pattern

Rename the table rather than dropping it, including a date stamp so the
intent is visible and reverting is trivial:

```sql
ALTER TABLE old_table RENAME TO old_table_deprecated_20240901;
```

This preserves the data, keeps the application from breaking immediately
(views or synonyms can bridge the gap), and allows validation that nothing
still reads the old name before the data is permanently discarded. After a
suitable observation period — typically at least one full release cycle —
the renamed table can be dropped with confidence.

## A real incident

A representative scenario: a developer cleaning up a legacy schema drops a
table they believe is unused, having searched application code for references.
A background ETL job that runs nightly has its query hardcoded in a scheduler
that was not indexed. The next morning the job fails, and the reporting
database built from it is now stale. Recovery requires a point-in-time restore,
which replays all other writes made in the intervening hours and requires a
maintenance window to apply them.
